# VeeLion Full-Stack Assessment (Express.js + Next.js)

## Overview

You are given a partially implemented **Task Management System**:

* `backend/`: an Express.js API with a **Tasks** module and an **Activity Log** module. Data is stored in local JSON files in `backend/data` (no database).
* `frontend/`: a Next.js (App Router, TypeScript) app with a **Task Dashboard** and an **Activity Feed**. Route handlers under `frontend/app/api/*` proxy requests to the backend.

Your goal is to review the existing code on both sides, improve the problematic parts, and build a new **Reports** feature end to end.

---

## Getting Started

```bash
# 1. API (http://localhost:3000)
cd backend
npm install
npm start

# 2. Web app, in a second terminal
cd frontend
cp .env.example .env.local
npm install
npm run dev
```

Every endpoint, including the Reports response your API must return, is documented in `frontend/docs/backend-endpoints.md`.

## Your Tasks

### 1. Code Review

Create a file named `REVIEW.md` at the root of the repository, with one section for the backend and one for the frontend. Document all the findings you would raise in a real code review, grouped under the headings that apply: Bugs, Performance, Security, Maintainability, Code quality, UX issues, React best practices.

For each finding, explain **what is wrong**, **why it matters**, and **how you would improve it**.

### 2. Refactor Both Sides

* Backend: the Tasks and Activity Log modules
* Frontend: the Task Dashboard and the Activity Feed

Don't rewrite everything from scratch, and keep all existing functionality working.

### 3. Build Reports End to End

**API:** create `GET /reports/tasks-summary`. It reads both the tasks and the activity JSON files and returns:

```json
{
  "total": 20,
  "byStatus": { "todo": 5, "in-progress": 10, "done": 5 },
  "recentActivityCount": 12
}
```

**Page:** create `/reports` in the frontend. Show the total number of tasks, tasks grouped by status and the recent activity count, fetched from your API, with loading and error states.

Follow a clean architecture on both sides and keep using the JSON files only.

### 4. Improve the UI

The app currently uses basic CSS. Use your eye and style the pages well.
